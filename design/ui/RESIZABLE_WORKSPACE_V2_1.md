# 화면별 가변 패널 및 스크롤 구성 (UI v2.1)

## 범위

본 변경은 Presentation 계층만 수정한다. Domain/State/Authority/Gate/API 및 서버 자료는 변경하지 않는다.
다른 작업자가 수행하는 PR #152(초기 공개 메뉴), #153(전용 도면 검토 화면)의 기능 코드는 수정하지 않는다.

## 공통 동작

- 넓은 화면: 구분선 드래그, 방향키 5% 조절, Home/End 최소·최대 폭, 더블클릭 또는 초기화 버튼.
- 목록만 / 분할 / 상세만 보기, 문서는 작성만 / 분할 / 미리보기만 보기.
- 폭 설정은 화면별로 브라우저에 저장하며 서버의 업무기록이나 사용자 권한에 영향을 주지 않는다.
- 실제 콘텐츠 영역 폭이 760px 미만인 경우 자동 단일 열 전환. 업무 상세를 선택한 경우 상세를 우선 표시.
- 넓은 화면: 목록과 상세가 서로 독립적으로 세로 스크롤. 좁은 화면: 일반 페이지 스크롤.
- 기존 서식 입력값은 보기 방식을 바꿔도 유지하고, 기존 업무 Command 및 서버 상태는 변경하지 않는다.
- 관리대장 29종: 테이블을 전체 폭으로 유지하고 한 개의 내부 스크롤과 기존 상세 Drawer 사용.

## 화면별 구성

| 화면 | 레이아웃 |
|---|---|
| 오늘 업무 | 우선 업무 / 상태·이력 가변 분할 |
| 검측·관찰·시정·공정·기성·계약·안전·준공 | 업무 목록 / 상세 가변 분할 |
| 발주처 보고 | 목록 / 결정 상세 가변 분할 |
| 감리 문서 | 작성 / 미리보기 가변 분할 |
| 관리대장 | 전체 폭 표 + 내부 스크롤 + 기존 상세 Drawer |
| 병렬 기능 검증(기존 도면 진입 포함) | 서버 기록 목록 / 상세 가변 분할 |

전용 도면 검토 화면 PR #153 병합 후에는 별도의 도면 뷰어 최적화가 가능하다.

## 검증

GitHub Actions (ubuntu-24.04)에서 UI Mock + Chromium으로 키보드/드래그, 비율 저장, 폼 유지,
독립 스크롤, 390px 모바일, 대시보드·관리대장 회귀 시험을 실행한다.
