## 기본 원칙

- 다섯 기능을 독립 worktree / PR로 병렬 개발한 후 통합 브랜치에서만 앱 진입점 연결.
- `Evidence`, `Location`, `Inspection`, `Issue`, `Action`, `InformationItem`, `RoleAssignment` 등 **정규 도메인 객체 유지**.
- 공사구역(현장 표현) = 기존 `Location` 객체. 신규 별도 위치 스키마 금지.
- 데이터 원본과 협업용 기록은 구분. 일반 대화·체크리스트 초안·기기 임시입력은 공식 시정완료/검측합격/발주자승인을 변경하지 않음.
- API에서 프로젝트 격리, 역할/공사범위 권한, `ExpectedVersion`, 멱등키, 작성자 및 이력 검증. 회신/검토와 최종승인 분리.
- `main`과 운영준비 서버는 통합 CI 및 현장 인수 전 변경/배포 금지. GitHub-hosted Actions CI, Mac mini 사용 금지.

## 참고 구현과 실제 Fieldwire의 기능 차이

동일한 사용자 업무 흐름을 우선 구현했으며 **Fieldwire 전체 기능과 완전 동등하다고 판정하지 않는다.** 아래는 추가 인수조건이다.

1. 사진: 촬영/업로드 메타데이터의 실제 모바일 EXIF, 오프라인 썸네일 캐시, 사진·도면·업무 역참조, 태그 다중 편집 UX.
2. 체크리스트: 항목별 사진 주석, 특정 공종의 체크리스트 일괄 배포, 보고서/PDF 출력을 포함한 현장 검증.
3. 공사구역: 대용량 공장 구역 트리, 기존 권한범위 유지한 상위구역 이동 및 드로잉 앵커 실기기 사용성.
4. 오프라인: **도면과 사진을 포함한 전체 데이터 스마트 캐시·파일 재시도·충돌 해결 UI·다기기 동기화는 미완료.** 현재 오프라인 실행은 기기 입력 대기열의 공식 서버 재전송에 한정.
5. 대화: 푸시/메일 실전송, 참조인 권한 변화에 따른 과거 알림 비노출, 첨부 자체 업로드와 UI 프리뷰 고도화.
6. 사용자 역할 ADM/SUP/CON/OWN/DES, PC/모바일/태블릿/저속망 전수 인수테스트; 현장용어/다국어 QA.
7. 출하 전 기존 전체 5개 감리 업무 E2E + 이전 도면/인증/문서/기성/준공 회귀 검증.
