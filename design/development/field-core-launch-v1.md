# DOUL 감리앱 1차 공개 범위 — 현장 핵심업무 v1

기준: 2026-10-11 사용자 결정. 이 문서는 **초기 사용자에게 제공할 화면 범위**를 정하며,
앱 전체 기능 구현 완료 또는 실제 운영 인수를 의미하지 않는다.

## 1. 최초 공개 업무

| 업무 | 최초 화면 | 기존 데이터·업무 활용 |
| --- | --- | --- |
| 현장기록 | `capture` | 사진·파일 원본, 메모·증빙 보존 |
| 도면조회 | `drawings` | 프로젝트 PDF 원본 조회, 페이지·확대·검색; **읽기 전용** |
| 검측 | `inspections` | 검측요청, 기준·증빙 연결, 결과·권한별 처리 |
| 지적·시정조치 | `corrections` | 현장 관찰·지적사항·시정조치 하위 화면 |
| 감리보고 | `owner` | 발주처 보고·회신 및 DOUL 양식 작성 하위 화면 |

**오늘**은 위 다섯 업무의 작업함이다. **관리**는 승인된 관리자만 사용하는 필수 기초설정 화면이다.

- 원본 자료, Domain Object, 버전, 감사이력 및 서버 측 권한 모델을 변경하거나 삭제하지 않는다.
- 공정·기성·계약·준공·전체 관리대장·기능 시험 화면은 현장 사용자 메뉴에서 노출하지 않는다.
- 기존 공식 기록 및 법정 업무 절차는 계속 유효하다. 화면에서 보이지 않는다는 이유로 법정 안전점검·통보·승인을 생략하면 안 된다.
- 지적사항·시정조치 및 보고 내의 원본 기록, 양식, 승인·회신 등은 기존 서버 허용 명령과 역할 권한을 그대로 적용한다.
- 도면 뷰어에서 어떤 PDF가 보이는 것만으로 **최신 승인도면**임이 증명되지 않는다. 승인 상태, 개정, 배포·수령 근거를 별도 확인한다.

## 2. 역할별 최초 화면

| 역할 | 보이는 기능 |
| --- | --- |
| SUP 감리 | 오늘, 현장기록, 도면조회, 검측, 지적·시정조치, 감리보고 |
| CON 시공 | 오늘, 현장기록, 도면조회, 검측, 지적·시정조치 |
| OWN 발주처 | 오늘, 도면조회, 지적·시정조치, 감리보고 |
| DES 설계 | 오늘, 도면조회 |
| ADM 관리자 | 감리업무 다섯 범위와 관리자 설정 |

각 세부 조작의 실제 접근 가능 여부는 서버의 소속 프로젝트·역할·자격·권한 검사 결과에 따른다.
역할별 메뉴 개수는 달라도 첫 공개 범위는 동일한 다섯 업무에 국한된다.

## 3. 설정과 안전장치

- 웹 **운영용 빌드와 개발·시험 서버**는 모두 기본적으로 `field-core` 화면 범위를 사용한다. 설정이 없거나 비어 있어도 다섯 업무를 표시한다.
- `VITE_DOUL_UI_SCOPE=field-core`: 개발 환경에서도 현장 핵심업무 화면으로 시험한다.
- `VITE_DOUL_UI_SCOPE=full`: 내부 개발·고급 기능 검증용 전체 화면을 **명시적으로** 활성화한다.
- `VITE_DOUL_UI_SCOPE`는 빌드 시점의 프론트엔드 표시 제어이며, **서버 API 권한 또는 법정 업무 접근 통제를 대체하지 않는다**.
- 비공개 업무의 직접 웹 URL은 오늘 화면으로 안내한다. 지적·조치·문서 등 기존 URL은 공개 범위 안의 해당 하위 화면으로 연결한다.
- React Native/Expo 개발용 앱은 아직 실제 로그인·PDF 조회를 포함한 현장 공개 인수 대상이 아니다. 1차 검증은 반응형 웹을 기준으로 한다.

## 4. 운영 공개 전에 반드시 검증할 항목

1. **실제 계정 로그인:** 관리자 발급 아이디·비밀번호, 로그인 유지/복구, 접근 중지; PR #148과 보안 인수 결과 필요.
2. **실제 프로젝트:** 소속 조직·관계자·권한·자격 및 감리자·시공사·발주처 접속 시험.
3. **실제 원본:** 승인·배포 근거가 있는 PDF 도면, 촬영 사진, 검측기준, 관련 법정 문서.
4. **업무 연결 시험:** 현장기록 → 검측 → 지적 → 시정자료 → 재확인 → 보고·회신.
5. **보고서:** 프로젝트별 필수 양식과 A4/PDF 출력·서명·수령 및 회신 확인.
6. **운영 보안 및 Pilot 인수:** 기존 현장 Pilot Issue #133, 릴리스 보안 Issue #134 등 필수조건 확인.

## 5. 확인 절차

- `npm run test:field-core`: 모의 데이터의 메뉴 범위·역할별 표시·도면 읽기 전용·하위 탭·직접 URL 제한 브라우저 자동시험.
- `npm run web:build`: 운영용 Web 번들 빌드.
- 이 자동시험은 실제 현장 사용자, 운영 로그인, 시정 완료 또는 법정 문서 승인에 대한 인수 증거가 아니다.

**공개 상태의 정의:** 코드·UI 준비 `≠` 실제 현장 공개. 본 범위와 별개로 운영환경·보안·원본자료·실제 사용자 인수를 완료해야 사용을 시작할 수 있다.
