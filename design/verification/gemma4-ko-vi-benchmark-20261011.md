# DOUL Gemma 4 한·베 번역 초기 벤치마크 (2026-10-11)

## 환경
- Mac mini M4 / 통합 메모리 16GB / Ollama 0.40.1.
- 로컬 Ollama API: 127.0.0.1:11434, 외부 노출 없음.
- 모델: `doul-gemma4-v2-agentic:q4`, Gemma 4 아키텍처, 11.9B, Q4_K_M, 약 7.4GB 설치.
- **프로토타입 성능 확인**, 통계적 품질 검증 및 운영 동시 접속 검증은 아직 진행하지 않음.

## 실측 결과

| 케이스 | 처리 방식 | 소요시간 | 결과 |
| --- | --- | ---: | --- |
| 베트남어 → 한국어 현장 문장 1 | 기본 `think=true`, 160토큰 | 19.47초 | 번역 출력 없음 |
| 베트남어 → 한국어 수치·검측 문장 2 | 기본 `think=true`, 160토큰 | 13.77초 | 번역 출력 없음 |
| 한국어 → 베트남어 도면 지시 3 | 기본 `think=true`, 160토큰 | 13.80초 | 번역 출력 없음 |
| 베트남어 → 한국어 단문 4 | **`think=false`**, 120토큰 상한 | **2.99초** | 출력 성공; 전문용어 오류 |

- 기본 모드 생성 약 **12.9 token/s** (세 케이스). 처리속도만으로 품질을 판단할 수 없다.
- 단문 테스트 원문: `Khu vuc truc B-3 chua lap dat day du thep dai.`
- 모델 출력: `B-3 구역에 띠용대(thep dai)가 아직 설치되지 않았습니다.`
- **전문용어 문제**: `thép đai`는 시공 맥락에서 *스터럽 철근/늑근*인데 모델의 `띠용대`는 부적절함. 축·위치 정보 B-3은 보존됨.
- 테스트 입력에는 무악센트 베트남어가 포함되어 있음. 정확한 베트남어 정서법 적용, 공식 용어집 주입, 더 많은 사례에서의 추가 평가 필요.
- 첫 세 테스트의 공란은 `thinking` 생성만으로 토큰 제한에 도달한 상황에 부합함. 단, 응답 내부 필드까지 확인한 원인 규명은 아니므로 확정 진단은 아님.

## 적용한 방어선
1. Ollama `think=false`, `temperature=0`; 본문 원문과 번역 결과 분리, 자동 업무기록 수정 없음.
2. 로그인 세션 및 프로젝트 역할 할당 검증 후 로컬 엔드포인트 호출.
3. 3000자 제한, 127.0.0.1/localhost 허용, 응답 텍스트 필수.
4. 도면번호·숫자의 기계적 일치 여부를 표시; 일치하더라도 의미 정확도는 검증된 것이 아님.
5. 모든 출력은 `automatic_unverified`/공식 발행 불가; 수동 검토 필요.
6. 현재 Mac mini Ollama는 루프백에만 바인딩. 서버를 인터넷에 직접 노출하지 않는다.

## 운영 전 필수 후속 검증
- 한국어↔베트남어 양방향으로 도면번호·검측 수치·부정형·명령/권한·정정·법적 효력 문구 포함한 최소 200건 Gold Set.
- 감리용어사전 강제 및 전문 감리자 검수, 정확도/치명적 오역률 기준 승인.
- 실제 API 서버가 별도 클라우드에 있다면 Ollama 연결을 위한 안전한 내부 연결(VPN 또는 전용 번역 워커) 설계. 현재 로컬 기본 설정으로 클라우드 배포 번역은 동작하지 않음.
- 2~10명 동시 접속 및 1분 이상 문서 번역 부하 테스트, 운영 감시·대기열·속도 제한.
- 공식 보고서/법정 서류 자동 발행과 자동 번역 대체 금지.
